## Implemented boundary

`server/provider.ts` owns the `ModelProvider` interface, including its optional caller cancellation signal. Default `MODEL_PROVIDER=ollama` keeps the current endpoint/model and decoder. `hosted` uses a server-only HTTPS Chat Completions base URL, model name and bearer key. No vendor SDK or automatic vendor fallback. Hosted requests always use strict JSON Schema. Both transports run the existing semantic validator, permit one repair, then fail closed. HTTP errors do not retry or expose response bodies/keys. HTTP requests refuse redirects and stop on caller cancellation or after 45 seconds per attempt (90 seconds for Year ahead). Ordinary reading output is capped at 1,200 tokens for hosted inference and `num_predict: 600` for Ollama. The handler selects 160 tokens for omen and chart-weather output and 240 for self-question insights and 900 for Year ahead on either HTTP transport; the injected Codex development provider does not set a token cap. Planning uses the shared budget and client deadline in the [adaptive question policy](../research/question-engine.md). Year ahead has a 200-second client timeout. Other reading requests retain a 60-second client timeout, which can expire before both attempts finish; measure and tune before deployment.

Candidate base URLs: DeepInfra `https://api.deepinfra.com/v1/openai`, Together `https://api.together.xyz/v1`, Google `https://generativelanguage.googleapis.com/v1beta/openai`. Verify the selected model's schema subset and thinking defaults before rollout; JSON schema support is not a semantic guarantee. [Together structured output](https://docs.together.ai/docs/inference/chat/structured-outputs), [Google compatibility](https://ai.google.dev/gemini-api/docs/openai).

`.env.example` deliberately leaves hosted settings blank. Set `HOSTED_MODEL_DISCLOSURE` and app `EXPO_PUBLIC_AI_PROVIDER_NAME` to the same clear vendor name. The app asks permission before sending; the server rejects missing/mismatched consent. Changing providers requires a rebuilt disclosure and new consent. Never put provider keys in `EXPO_PUBLIC_*`.

## Public endpoint and limits

The Supabase `predict` function uses `server/hosted-limits.ts`, which verifies every inference caller with Supabase Auth's `/user` endpoint. Anonymous Supabase sessions are valid identities; an API key alone is not. Planning, omen and insight clients now carry the same session as forecasts. The attribution-only `heard` action remains identity-free and cannot call a model. Platform `verify_jwt=false` permits modern signing keys; the handler enforces authentication itself. The separate RevenueCat function keeps its existing webhook authentication.

`202610200010_hosted_limits.sql` supplies service-only RPCs and tables. Atomic row locks enforce **reserved + accounted usage <= $25 per UTC calendar month**, across users, functions, repairs and social inference. Each outbound HTTP attempt reserves the full 262,144-token context plus its output cap at the more expensive priority rates ($0.15 input / $0.225 output per million), checked against [DeepInfra's model page](https://deepinfra.com/Qwen/Qwen3.5-9B) on 2026-10-20. A normal 1,200-output attempt reserves $0.0395916. Valid usage releases excess reservation and accounts tokens at those ceiling rates, conservatively above standard-tier invoices. Missing usage, aborts, errors and lost responses retain their entire reservation. Settlement is idempotent; reservations never expire automatically. Database outages refuse inference. The last five minutes of a UTC month refuse new reservations so a 90-second attempt cannot cross its billing boundary. Unknown usage can exhaust the allowance early; the operator must reconcile against invoices rather than deleting holds.

Daily admission uses the server's existing allowance: first 20 free questions, then 1/day; Plus 10/day; packs and earned bonuses remain available. A shared reading-attempt quota permits one retry per available question (2 attempts per slot), including failed generations, across predict, bond, friend and Circle. Existing successful-reading billing still decides which results can be delivered and charged. Planning gets 6 attempts per slot, sharing drafts 4; omen 2/day, insight 3/day, chart and Year ahead 2/day each. Days use server UTC, never the supplied device date. Each request's admission covers its classification, generation and repair calls; each call separately reserves money. New identities cannot bypass the global ceiling. Configure Supabase anonymous-signup rate limits/CAPTCHA for the tester project to reduce identity churn.

Run `TMPDIR=/tmp/fm-cb-hosted-readings python3 scripts/verify-hosted-limits.py` to drive the actual migrations on disposable PostgreSQL, including competing admissions at the exact ceiling and daily quotas. `tests/hosted-limits.test.ts` covers the shared provider's repair/accounting order and public boundary. Neither proves DeepInfra output quality or hosted Supabase compatibility.
