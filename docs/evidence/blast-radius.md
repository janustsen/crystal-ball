# Shared boundary verification

The critical invariant is that malformed model output cannot become a displayed prediction or consume a reading. The provider uses the same schema/validator for both attempts, then throws; the handler returns a typed error; the app only calls savePrediction on kind=ok. tests/engine.test.ts actually runs the provider against repeated malformed JSON and observes exactly2 calls followed by rejection (level4). The real UI offline drive observes retained answers and unchanged allowance before retry, then one saved prediction after success (level5).

Moving question policy to src/questions.ts changed the server and client boundary together: the client uses adaptPlan for dependent event options; server validates invalid tournament years. The executable test proves NBA contenders and men's/women's editions differ correctly, and requested Danish/coding never become Spanish. All known-fact skip and min/max/Other checks still pass across the registry. This is evidence of policy mechanics, not a guarantee of model semantic relevance.

Supabase's JSON state crosses the device/storage/database boundary. scripts/verify-cloud.mjs exercises actual anonymous auth and RLS, not mocks: owner sees1 test row, other user sees0, cross-user write is rejected. scripts/observe-mirror.mjs compares the actual browser-drive saved facts/history to its own authenticated database rows, omitting values from the evidence report. Offline mirror retries and Apple native linking remain unproven beyond source/types; do not present them as native end-to-end passes.

The shared live research path uses public topic queries only; personal facts remain in local model requests. Source leads are not full articles and cannot establish future accuracy. General output and sensitive-topic coverage remain model-quality risks tracked by the generation graders. Production auth/rate limits and payment entitlements are explicitly outside the loopback test adapter; exposing it publicly is not supported.

The provider validator supports an awaited verdict as well as a boolean. Its critical invariant is still two generation attempts maximum, with no unvalidated result returned. The async rejection test invokes the actual provider and observes exactly two fetches then rejection; all schema callers type-check. A real 20-case engine replay also produced a recoverable chess error after semantic rejection, rather than returning the rejected text. Semantic review itself uses the same local provider; each review has its own schema-repair bound, so the maximum number of model calls increases. The 60-second client timeout remains the user-visible bound; local model processing is not automatically canceled by client disconnect. This latency/cancellation limitation is retained, not claimed solved.

The Expo compatibility check moved three packages to the current SDK-57 patch set (Expo 57.0.26, constants 57.0.20, router 57.0.24). The matching-surface check is a clean Metro restart followed by the real drive and export. `npm audit --omit=dev` reports 14 moderate dependency-chain entries, no high or critical entries; `dependency-audit.json` retains them. npm proposes major downgrades for several SDK packages, so automatic `audit fix --force` was not used. These upstream advisories remain a limitation, not a clean-audit claim.

The explicit JSON schema is now also included in the system prompt. The newer local Qwen3.5 returned literal allow or a wrong classification key without that prompt, despite the API format field. The focused replay then returned the correct category object and valid card/review objects. Client wire types are unchanged: the schema and semantic checks still gate every result. Candidate-model and selected-model runtime results must remain separately labeled.

React Native Web 0.21 does not translate accessibilityState.checked into aria-checked in its createDOMProps path. Native state is retained and explicit aria-checked/selected/expanded properties supply web semantics. The real card drive observes aria-checked=true, zero axe violations, and Other plus Next visible at both phone sizes. Removing the decorative container label cleared the prohibited-attribute defect. This is executed browser proof, not native screen-reader proof.

The experimental card reviewer was removed after actual 20-case replays completed only10/20 on both models. This removes an unreliable blocking call; it does not loosen structural card validation, the sensitive-topic gates or final forecast consistency review. The clarified-prompt fixture was insufficient evidence to retain that reviewer. The candidate comparison preserves this reversal and its limits.

The returning-user general flow exposed unrelated memory leakage: Spanish practice and savings appeared in novel-writing options. `known-context-probe.json` reproduces it with real inference, comparing identical questions with and without those memories. General planning now receives only its question; durable memories belong to the typed topic registries, and general cards are session-only. A regression test failed on the actual model request boundary before the fix and passed after it. Typed domains still receive their known facts for skipping. Historical wrong cards remain in general-flow-unrelated-memory.json and general-card-unrelated-memory.png.

A later 9B comparison exposed an additional boundary defect: schema-extra reason/assumption fields could overwrite a deterministic explanation, or throw text.toLowerCase when their types were wrong. The bounded path now always keeps its server-owned explanation and ignores unused model fields. A real 9B replay captured the failure; the new regression reproduces it with reason 42 and an object assumption, fails before the one-line fix, then passes. The generic path still validates both strings before using them. This is a concrete trust-boundary correction, not a model-quality workaround.

The former general-output contract used an enum-selected basis key and a speculative assumption. Its regression checked invalid-basis repair and exact display of the recorded input. The explanation format has since changed; the [voice guide](../voice.md) owns the current contract.

The future-consistency reviewer was subsequently removed: the actual trace in owned-basis-diagnosis.json rejected assumptions for not proving future events. The 20-case replay and general browser flow recorded here passed with the former quoted-context format; they do not validate the later insight format. Input/output sensitive-topic checks and the shared provider's one-repair behavior remain active.
