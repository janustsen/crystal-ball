# Run Crystal Ball

This checkout is an Expo React Native prototype. It runs anonymously, using local Ollama and optional local Supabase. No hosted credentials are included. Current verification uses Expo web390×844 because this Mac has Command Line Tools but no Xcode/iOS runtime. Native integrations are not claimed simulator-verified.

## Local development

1. `npm install` (Node22+).
2. Start Ollama with task-local models and a dedicated port: `OLLAMA_MODELS="$PWD/.local/models" OLLAMA_HOST=127.0.0.1:11435 OLLAMA_NO_CLOUD=1 ollama serve`. In another shell: `OLLAMA_HOST=127.0.0.1:11435 ollama pull qwen3:4b-instruct-2507-q4_K_M`.
3. Install Supabase CLI, then `supabase start` from this checkout. Project id crystal-ball-prototype uses55321API,55322Postgres,55323Studio. Docker is required. Anonymous auth is enabled; migrations install per-user row-level policies. `supabase status -o env` displays this local project's keys. Never use another project's key.
4. Copy `.env.example` to `.env.local`. Populate only EXPO_PUBLIC_SUPABASE_ANON_KEY from the local output. This public local anon key is not a service-role key. The app remains local-first if cloud mirroring is unavailable; it retries on the next state change.
5. `npm run server`, then `npm run web -- --host lan`. Open http://localhost:8087 or this iMac’s private Tailscale URL http://janus-mac.tail8d2280.ts.net:8087. Leave EXPO_PUBLIC_ENGINE_URL unset for web: Metro forwards same-origin `/engine` requests to the loopback engine, including `/engine/share` and `/engine/health`. A native simulator still defaults to http://127.0.0.1:8787. The bridge is development-only; keep this preview on the trusted private network. `npm run web` generates/reuses a 256-bit secret in ignored `.local/preview-secret` (mode 0600) and injects it into the web client at startup. Browser authentication uses username `preview` and that file’s contents as password. The JavaScript bundle is also authenticated, so an unauthenticated client cannot recover the injected key. The Expo HTML shell is public but contains no key. Engine/export/health calls require the key plus a same-origin Origin header. Direct `expo start` without the injected key fails closed. Rotate by stopping the preview, deleting only `.local/preview-secret`, and restarting with `npm run web -- --host lan --clear` so Metro rebuilds the embedded key; existing clients must authenticate and reload. Never publish this development bundle or its credentials. Animated MP4 exports additionally require `ffmpeg` on PATH; still PNG export remains available if it is missing.
6. `npm run check && npm test`. Follow the [verification skill](.agents/skills/verify-crystal-ball/SKILL.md) for the current browser drives, remote bridge check and evidence requirements.

Local no-mistakes reviews also require `semgrep` and `gitleaks` on PATH, installed project dependencies, and an up-to-date `origin/main` ref with enough history to resolve its merge base with HEAD. See [the gate configuration](.no-mistakes.yaml) for the security checks and owner-disposition policy; `npm test` alone does not run these gates.

The server reads server-only variables from its shell, not Expo's public env loader. Keep MODEL_PROVIDER=ollama. No paid inference occurs by default. Local addresses work in an iOS simulator; a physical phone needs a trusted LAN-accessible development server and matching EXPO_PUBLIC_ENGINE_URL/Supabase URLs. Do not expose the unauthenticated local Node adapter publicly.

## Known prototype boundaries

Remote HTTP origins cannot access browser speech recognition. The Ask flow offers typing when voice is unavailable; localhost or an HTTPS origin plus microphone permission is needed for real browser recording. The current iMac has no ffmpeg, so MP4 export reports a recoverable error; PNG export works. Supabase is optional and not running here: local history and memory work, cloud mirroring does not.

Forecasts are speculative, never proven future knowledge. Sensitive requests soft-block; classification fail-closed errors consume no reading. English plus a few Spanish/Danish phrase patterns is not multilingual safety coverage. Seeded Explore is visibly labeled. Apple save and web notification controls explain their native setup requirements. Friend links carry only the question and friend flag, not private answers. No App Store submission, public posting or real payments are part of this build.

Apple wiring now uses Apple.signInAsync followed by Supabase.auth.linkIdentity with the ID token, preserving the anonymous UID. It stays disabled until EXPO_PUBLIC_APPLE_LINK_ENABLED=true and the provider is configured. This is account wiring, not a verified native sign-in claim. The native purchase adapter can initialize RevenueCat and restore sandbox purchases; the current paywall deliberately remains mock.

### Daily omen widget and check-ins

Home generates one personal astrology-flavored omen per local anonymous profile/day, using remembered facts and `facts.sun_sign` when onboarding supplies it. The existing engine accepts `action: "omen"`; the model output is capped at 160 tokens. Local Ollama remains the default (no service spend). The shared provider keeps one constrained repair on invalid output, then fails closed. No reading credit is spent. One generation request is claimed durably before inference; failures remain unavailable for that day rather than retrying on each visit. This is the prototype's device-local quota, not a cross-device server quota. Forget everything erases the private omen and widget while preserving the daily generation claim, plan and credits.

The iOS `DailyOmen` widget uses the `expo-widgets` config plugin in app.json; `npx expo prebuild --platform ios --no-install` generates its extension and app-group entitlement. A development build is required (not Expo Go). Open Home before adding the widget. It displays the same personal omen, then switches to “Open the Ball for today’s omen” at the next local midnight; the widget never triggers model calls. Web and Android show the omen on Home without a native widget.

Check-in scheduling uses a valid forecast `dueDate` (YYYY-MM-DD) at local noon, falling back to creation date plus 30 days when the date is absent or invalid. The current engine does not produce `dueDate`; ball-set dates depend on the cb-reading-flow PR. Retention consumes that contract without generating dates. See [README](README.md) for automatic scheduling, permission and outcome controls.

Device widget rendering and notification delivery/tap navigation remain unverified until Xcode setup is complete. Evidence and boundary limits are in `docs/evidence/retention-validation.md`. After creating a real reading in a named chrome-devtools-axi session, `scripts/drive-retention.sh` repeats the retention checks; its default session is `cb-retention` (override `CHROME_DEVTOOLS_AXI_SESSION` when needed).

For concurrent local verification, set `CRYSTAL_BALL_ENGINE_PORT` on both the engine and Metro to select a task-owned loopback engine port; it defaults to 8787. Keep `EXPO_PUBLIC_ENGINE_URL` unset so browser calls retain the same-origin bridge.
