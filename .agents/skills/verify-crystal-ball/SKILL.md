# Verify Crystal Ball

## Launch
Run from this checkout. `npm install`, then `npm run server` (127.0.0.1:8787) and `npm run web -- --no-dev --minify --host lan --port 8087` (localhost:8087, no dev overlay). Keep each command's PID/session for teardown. Concurrent worktrees must use separate ports and a checkout-local `TMPDIR` (for example `.local/tmp`) for Expo, because shared Metro transforms can reuse another lane’s public environment variables. The server accepts `PORT`/`APP_ORIGIN`; use the same `ENGINE_PORT` for Expo’s bridge. Current drivers accept `PREVIEW_URL`, and the launch driver accepts `APP_URL`. Ollama must already serve the local Qwen model at 127.0.0.1:11435; SETUP.md documents isolated model storage. Do not stop another checkout's servers. For recorded Simulator coverage and its limits, see [verification evidence](../../../README.md). For ritual Simulator checks, see features/ritual.md. Supabase is optional. Native checks require Xcode and a development build; do not claim browser checks as native proof.

This lets the private Tailscale preview use the iMac engine rather than the MacBook's loopback. Keep the development server on the trusted private network.

For public-provider/auth/budget changes, also follow the [hosted readings checks](features/hosted.md): real migration races and consent/limit-message browser drives, followed by the credential-dependent DeepInfra comparison and deployed smoke. Local Node remains a development surface and does not prove the public auth boundary.

See [SETUP.md](../../../SETUP.md#local-development) for preview access and client-token constraints. Use a fresh profile without HTTP credentials to verify page access. Never put the token in evidence.

Use `CHROME_DEVTOOLS_AXI_SESSION=crystal-ball chrome-devtools-axi open http://localhost:8087 --full`, then `emulate --viewport "390x844x1,mobile,touch"`. For remote-preview work also open http://janus-mac.tail8d2280.ts.net:8087. Use only the named profile. ## Motion audit
After the functional drives finish, run `node scripts/drive-motion.mjs` on its own. It uses a fresh named chrome-devtools-axi profile, captures perf-start/perf-stop traces at 390×844, counts WebGL1/WebGL2 indexed and non-indexed draw frames and display frames through each interaction, and closes only its own browser. Do not run other browser drives or bundle builds concurrently with the timing sample. The trace covers idle Home glass, approach, listening, typing, the returned one or two questions, thinking/reveal, sharing, tabs and 45 seconds of ambient sky. Targets: >=58fps for display frames and for room-glass draw frames while the ball stays visible, p95 <=20ms, no sampled frame >50ms and no long main-thread tasks. Keep failed measurements with their cause; do not replace them with an unexplained pass.

Inspect the room: the live glass ball must stay on its tracked ring through flights and at Home and while listening. Follow the [room contract](../../../docs/design/motion.md#room) for the supported still fallback and reduced-motion fades. Run `node scripts/check-motion-accessibility.mjs`. Toggle Reduce motion and confirm the canvas stops drawing and CSS animations stop; repeat with the OS preference and verify Home's ball and Tap to ask remain visible at large text. Native `Animated` uses its native driver, but an iOS bundle is not evidence of device frame rate. If no simulator/device is available, report that remaining boundary explicitly.
