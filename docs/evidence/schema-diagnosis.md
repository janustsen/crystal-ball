# Local decoder regression

Reproduced the actual holiday prediction from engine-bakeoff.json with local Qwen. The schema's literal-horizon regex produced HTTP 500 and hundreds of repeated symbols. Changing only to the previous simple You/Your prefix pattern returned valid JSON in 1.35 seconds. Removing only maxLength still failed after 16.79 seconds. The same prompt was used, so prompt content and maxLength alone did not explain this failure. Raw matrix results are in schema-diagnosis.json; original error is in schema-error.txt.

Fix: retain the simple schema, validate the model verdict, and format the already-supplied horizon in server code before semantic validation and output. This does not choose a replacement outcome. The semantic reviewer sees the final composed headline. The async provider still permits one repair, then fails closed. The original request now succeeds; the full runtime replay records broader reliability.

A focused formatter test was run red before implementation and green afterward, covering negative verdict preservation, already-present horizons and a bare duration. Real-model replay remains necessary because a mocked JSON parser cannot reproduce Ollama's decoder. Debug instrumentation is confined to ignored .local probes; no request-body logging was added to production.

Further replay found the simple prefix pattern could also trigger the decoder failure for a different question. The final implementation removes regex patterns from the local generation schema and enforces phrasing after decoding. It normalizes optional Yes/No sentence prefixes while preserving the explicit positive or negative verdict. A bare Yes/No remains invalid and receives specific repair feedback. Four previously failing questions now pass in semantic-failure-diagnosis.json; semantic-prefix-failure.json and semantic-failure-first-run.json preserve the prior failures.

The semantic checker previously rejected a job forecast merely because no job search was supplied, even though employment experience and learning were supplied and the answer was explicitly speculative. It now checks factual contradiction instead of requiring proof of the future. That experiment used separate present-fact reasoning and speculative-assumption fields; the current explanation contract is in the [voice guide](../voice.md). Fabricated numbers and unrelated causal claims remain rejection criteria.

## Prediction length constraints

The prediction schema in `server/engine.ts` leaves string lengths unconstrained during decoding so the decoder can finish the sentence. Application validation retains the 90-character qualitative prediction limit and the 110-character final headline limit, including the supplied horizon. Qualitative predictions must end in a period or exclamation mark before horizon formatting; invalid output receives one repair, then fails closed. This punctuation check does not prove semantic completeness. `tests/prediction-quality.test.ts` covers the reported cut-off cooking prediction, successful repair, and rejection when repair repeats it.
