# Launch foundation blast radius

The hosted-transport addition preserved existing provider callers in `server/handler.ts`, local Node and the Supabase edge function. See the [implemented provider boundary](hosted-model.md#implemented-boundary) for the current contract. Hosted requests add an explicit consent requirement; older clients are rejected when a server is switched to hosted. This is deliberate: an old local-only disclosure cannot authorize sending private inputs to a new vendor.

Safety fact: neither transport can return model JSON unless the existing validator accepts it; each gets at most one repair. `tests/provider.test.ts` calls the real provider for both output formats, verifies feedback is sent, invalid replies fail, transport errors do not fall back, and the handler rejects missing/outdated consent. This is executed transport-boundary proof with HTTP responses substituted, not hosted model quality evidence.

Backup safety depends on two facts: ownership remains scoped to `auth.uid()`, and local entitlements never come from cloud history. `scripts/verify-backup-db.mjs` applies the production migrations to isolated PGlite PostgreSQL and exercises real RLS with synthetic users. It proves a copied reading can coexist under two owners, cross-owner reads are hidden, cross-owner upserts are rejected and deleting one owner's rows preserves the other. Output: `docs/evidence/launch-backup-rls.json`. No shared database was altered. `tests/backup.test.ts` checks the archive decoder. `tests/cloud.test.ts` verifies replacement restoration, read-only failures, owner checks and last-device-wins uploads. `scripts/verify-backup-cancellation.mjs` drives the real React store with native/storage boundary mocks to cover hydration locks and offline deletion across restart.

`src/cloud.ts` reads the current session instead of caching an anonymous UID across a login. It pages remote history and rejects malformed payloads before state replacement. `src/store.tsx` drains prior writes before authentication; it locks mutations during hydration and manual backup, and failed restore reads leave local state unchanged. `tests/cloud.test.ts` uses the installed Supabase client/query builder with substituted HTTP responses to check complete newest-first pagination, replacement restoration, failed reads and upload ownership. Malformed payload rejection is covered at the decoder boundary by `tests/backup.test.ts`, not through a cloud restore test. Native restore ordering is source-reviewed, not device-proven. Apple tokens, nonce exchange and initial sign-in cancellation still require the configured iOS device drive. Account switching is deferred in the [linked-account Restore handoff](verification.md#linked-account-restore-clarification).

Remaining risks: migration must precede the new `onConflict:user_id,id` client; multi-device concurrent fact/outcome edits remain last-write wins; offline failed reset is not guaranteed remote deletion; linked account deletion/revocation is not implemented. Apple remains disabled by default. The loopback development server still lacks production auth and quotas. No public launch is claimed.

Reproduce: `npm run check && npm test`; install PGlite under `.local/pg-proof` as described at the top of the database script, then `node scripts/verify-backup-db.mjs`. Run the project's verification skill on the final merge head; follow [local port configuration](../../SETUP.md#local-development) for an isolated lane and set the drivers' `APP_URL` and `ENGINE_URL` accordingly.

## Codex development boundary

The common validator was extracted without changing `ModelProvider.json`; Ollama, hosted HTTP and Node-only Codex all execute it. `tests/codex-provider.test.ts` launches a fake executable through the real subprocess boundary and proves model arguments stay separate, prompts use stdin, API-key environment overrides are absent, invalid output receives one repair, and temporary files are removed. It also proves the deployed factory and production mode reject Codex. The real subscription-backed CLI and browser drive separately establish actual inference works. No Codex import reaches the Supabase edge entry point. The existing Ollama verification remains required after integration; Codex results supplement it.

## Greptile restore repair (2026-10-01)

The missing-archive guard runs at `restoreBackup`, before the store can persist a replacement. A saved empty archive still has a knowledge row and remains restorable. `tests/cloud.test.ts` drives the real Supabase query consumer with synthetic HTTP responses: missing archive failed before the repair (`Missing expected rejection`) and now rejects without writes; intentionally empty archive restores successfully.

Restore now reuses an existing Apple-linked session, just as Save does. It no longer opens a second Apple sign-in that could switch accounts before a failing archive read. `node scripts/verify-apple-restore.mjs` drives the real BackupPanel and Store in React, replacing only native/auth/storage boundaries. Before the repair, auth changed to account B while backupOwner remained A. Afterward the failed read preserves account A and local bytes, and a subsequent setting change successfully uploads to A. This is executable boundary proof, not native-device Apple verification. Fresh-phone sign-in remains on the existing unauthenticated path; one device/account at a time remains the supported archive policy.

The authorized follow-ups are deletion-query URL growth with long histories and propagation of client cancellation into model transports. Neither is claimed fixed here.
